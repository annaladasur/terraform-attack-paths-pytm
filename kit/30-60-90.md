# Implementation readiness checklist

Choose scope and pace under your own policy. This legacy filename does not prescribe a calendar. No reports are requested. Move to enforcement only when evidence, authority and operating capacity support it.

Scope the first pass to **one repository and one Terraform root module that holds data you care about**. Improve the
review you already do before replacing any tool.

## Scope the problem

- [ ] Name the root module, its owner, and the person who owns this pilot.
- [ ] Write your own before/after sentence ([`README.md`](README.md) has ours).
- [ ] Check that you can produce a plan in CI with a read-only role. If you can't, start with a scheduled job that
      can, and add the PR check once the role exists.
- [ ] Tag the data stores that matter (`data_classification = "confidential"`), or plan to run with
      `--heuristic-sensitivity` and treat every path as `review`.

## Observe and record a baseline (Level 1)

- [ ] Add the job from `../examples/github-actions/pr-security.yml` (or the GitLab one) with `TAPM_LEVEL=observe`.
- [ ] Add `../examples/github-actions/nightly-canary.yml`: the `default-branch` job gives you open paths on main.
- [ ] Copy `baseline-worksheet.csv` to a place you keep. When the sample supports a useful comparison:
      `tapm measure <run dirs> --worksheet my-worksheet.csv --at baseline`.
- [ ] Fill the manual rows. M9: median hours from PR opened to security sign-off over your last 10 merged Terraform
      PRs. M16: how many root modules have a threat model that matches their current code.
- [ ] Record what reviewers read today per Terraform PR (M1 is filled for you when your scanners' output is in
      `baselines/`).

## Examine recommendations and verify the control (Levels 1 → 2)

- [ ] Switch to `TAPM_LEVEL=recommend`. The PR comment shows paths, questions and "would block".
- [ ] Run `tapm gate <main run> --tf-dir <dir> --draft` on the default branch. Give every path already open an owner,
      a reason and an expiry in `attack-path-exceptions.yaml`, or open a ticket to fix it.
- [ ] Commit an empty `threat-answers.yaml` next to the Terraform, and ask authors to answer the first-screen questions.
- [ ] Add [`CODEOWNERS.example`](CODEOWNERS.example) lines for both files.
- [ ] Upload `attack-paths.sarif` to code scanning if your code host has it.
- [ ] At a suitable cadence, sample the reported paths and mark each one reachable or not reachable. Record M8.
- [ ] Compare a new measurement with the baseline. Legacy `--at day30` / `day90` / `day180` labels are optional worksheet slots, not deadlines.

## Decide whether to enforce (Level 3)

- [ ] `TAPM_LEVEL=validate`, required check on the pilot repository.
- [ ] Run the remediation loop on new paths (`tapm run --remediate`, or `make remediate` to see it) and merge only
      verified fixes. Record M7.
- [ ] Watch M9 at your chosen review points. If decisions slow down, look at M8 (false paths) before anything else.
- [ ] Confirm the owner split in [`prerequisites.md`](prerequisites.md): AppSec owns the threshold, repo owners own
      answers and their accepted risks.

## Tighten acceptance and continuously validate when justified (Levels 4 → 5)

- [ ] `TAPM_LEVEL=prevent` on the pilot: accepted risks need a compensating control and an approver who isn't the
      owner, and run at most 30 days.
- [ ] Add one canary of your own: a small root module with a known path (`canary.yaml`: `expect: block`) and one
      without (`expect: pass`). Point the nightly `tapm canary` at them.
- [ ] Re-measure at a suitable review trigger. Compare M3, M5, M9 and M12 to baseline.
- [ ] Decide on expansion: the next root module, or the next repository.
- [ ] Retain the decision and evidence locally under your information policy. No external report is requested.
